# US Regional Model Trainer (`sms_model_us.bin`)

Trains the BiGRU + CRF multi-task NLU described in `.ai/ML_MODEL_TRAINING_GUIDELINES.md`
and exports it in the binary tensor order `ModelWeights.load()` reads.
`MODEL_TRAINING.md` notes the trainer was never in this repo; this is it.

## Run

```
python3 -m venv .venv && .venv/bin/pip install numpy
.venv/bin/python train.py            # phase 1 pretrain + phase 2 finetune -> weights.pkl
.venv/bin/python export.py           # -> app/src/main/assets/models/sms_model_us.bin
.venv/bin/python verify.py           # re-reads the .bin, checks it against the float model
.venv/bin/python fixture.py          # builds the 50-message parity fixture
javac -d . Parity.java && java Parity ../../../../app/src/main/assets/models/sms_model_us.bin fixture.tsv fixture_jvm.tsv
diff fixture_py.tsv fixture_jvm.tsv  # must be empty
```

## Architecture

| Component | Value |
|---|---|
| Tokenizer | `[A-Za-z0-9]+|[^\sA-Za-z0-9]` over lowercased `"<address> \| <body>"` |
| Buckets | FNV-1a over UTF-8 trigrams, `VOCAB_SIZE=4096`, `MAX_TRI=8` |
| Token vector | **mean** of its trigram embeddings (word forms share trigrams, so `debit`/`debited`/`debiting` overlap by construction) |
| Encoder | BiGRU, `embDim=48`, `hidden=64`, gate rows `[reset \| update \| new]`, `h=(1-z)*n+z*h_prev` |
| Heads | `isBank` (2), `ttype` (3), `src` (3) off the mean-pooled `enc`; 11-tag emissions per token + `crfTrans[11x11]` |
| Params | 240,051 float32 -> int8 per-tensor scale -> 237 KB |

Two phases, as the doc requires:
1. **Self-supervised** CBOW over trigram buckets with negative sampling — shapes the
   embedding table so contextually interchangeable money verbs land near each other.
2. **Supervised finetune** — CRF NLL + three weighted cross-entropies, Adam, grad-clip 5.0,
   30 epochs, best-checkpoint selection on val.

Backprop is hand-written (no autodiff dependency) and gradient-checked against finite
differences for `emb`, both GRU directions, all four heads and `crfTrans`.

## Labels

`us_training_corpus_v1.csv` carries the OLD parser's own predictions in `is_transaction` /
`txn_type` / `source`, and that parser is the one measured at ~90% with ~30 false positives
(non-events scored as executed transactions). Training on its output would bake the bug in,
so `labeler.py` re-derives labels from message semantics and `spans.py` derives the BIO tags
from field regexes projected onto token offsets.

The re-derived `is_transaction` labels were validated against the per-batch
`expected_summary` ground truth in `automation/processed/*.xml`:

| Batch | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|
| labeled vs truth | exact | exact | +1 | exact | exact | exact | exact |

Batch 6's +1 is the deliberate verbatim-duplicate PETCO SMS: two identical messages must get
the same label, while the ledger counts the movement once. 141 exact duplicate rows
(the double-ingested batch 3, plus repeated OTP/promo/personal texts) are dropped, leaving
**900 unique messages** — 541 executed, 359 non-events.

## Results

Held-out val = 134 messages (15%, stratified), never trained on.

| Metric | val | train |
|---|---|---|
| isBank accuracy | 1.000 | 1.000 |
| isBank precision / recall / F1 | 1.000 / 1.000 / 1.000 | 1.000 / 1.000 / 1.000 |
| ttype accuracy | 0.978 | 1.000 |
| src accuracy | 1.000 | 1.000 |
| CRF tag-token accuracy | 0.993 | 0.999 |
| field exact match | BANK 1.000, BALANCE 0.985, ACCOUNT 0.981, AMOUNT 0.972, MERCHANT 0.878 | BANK/AMOUNT/BALANCE 1.000, ACCOUNT 0.987, MERCHANT 0.973 |

After int8 quantization, the exported `.bin` agrees with the float model on **99.78%** of all
900 rows and scores isBank 0.999 / ttype 0.997 / src 1.000 / tag-token 0.998 against labels.

MERCHANT is the weakest span (0.878) — merchant names have no cue word as reliable as
"ending"/"Avail bal", and the weak-supervision regexes that produce its labels are themselves
the noisiest. It is also the only field no ledger arithmetic depends on.

## Parity fixture

`Parity.java` is a line-for-line JVM port of `ModelWeights.load` + `Tokenizer` + `GruCell` +
`CrfDecoder` + `SmsParser`. Run against the same `.bin` on 50 messages (25 executed, 25
non-events) it reproduces Python's **tokens, trigram ids, tag paths, all five field spans and
all three head outputs identically** — which is what proves the little-endian header, the
signed-byte dequantization (`value = byte * scale`) and the 18-tensor order are right.

`FUTURE_MARKERS` in `tok.py` and `Tokenizer.kt` must stay identical. This commit adds
"scheduled for" / "scheduled on" to **both**: US banks phrase future-dated payments that way,
and a marker present on one side only shifts every embedding lookup by one position — the
silent-degradation failure `MODEL_TRAINING.md` warns about.

## Caveats

- The corpus is **synthetic**, generated by this repo's own batch generator. `MODEL_TRAINING.md`
  Step 1 is explicit that synthetic-only training scores well against your own generator and
  fails on the first real bank that words things differently. These numbers are an upper bound;
  real-SMS validation is still required before shipping.
- Labels are weak supervision, not human annotation. Where the rules and the model disagree on
  held-out data, the rules are treated as truth — so the val numbers measure agreement with the
  labeling function, and inherit whatever it gets wrong.
- Trigram bucket collision check (`MODEL_TRAINING.md` Layer 2) has not been run on the top-500
  tokens; 4096 buckets is inherited from the India model, not re-derived for US vocabulary.
